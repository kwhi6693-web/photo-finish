# 原生保真调色与实际保存

光色调整、自然材质/文字保护与认可版本精修，先核查当前真实可用的非生成和区域工具；能完成表达时采用原生路线，不以“修图”或“更自然”为由默认重建全图。需要新增/替换内容且保护允许才选择生成，强弱光色表达仍由专业判断决定。工具可见不等于本任务可用：先取得输入、实际mask（局部时）和正式输出验证，不能凭接口名称通过。

选区每次只命名一个目标，实际查看mask是否漏选/误选，再编辑；不能把“保留树木”等多对象约束塞进单目标选择词并假定理解正确。蒙版外零像素差只是非目标字节依据，目标是否改善、边缘与整体协调仍须目视。存在误选就停止或修正mask，不靠增强描述反复生成成片。原生调色不恢复已重建的植被结构；指定V1返工必须继续用V1，无法改善则保留失败，不偷换原片或登记V2。

本页为按需接口，氛围、审美、构图与去AI味沿总规范执行，不预设微调上限。日常submit逐保护目标记录fidelity策略：实际非生成原区域保留用native_preserved，真实局部编辑避开保护区域用local_excluded；均需实际能力依据、修正路线和最终比较，不以工具名称自动通过。普通生成后可见内容比对用generative_compare；exact_content不得选择此路线。

1. 实际看原片、完成源绑定参考选择与保护契约，先判断当前工具路由与已有明确授权。单图已有明确代做授权时使用获准的服务端路线；仅照片不推断为代做授权，不能用下游检查或保存来制造工具授权。需先开交互卡片且工具明确要求STOP时，调用后结束，不继续服务端或其他工具；未返回正式文件URL只记录预览。组件故障仅按工作流实际收到的信号判断，不将网页提示伪装成工具失败回执。调用前可证实的不可用例外按当次规则处理，不覆盖STOP；不具备条件则说明阻塞及最小明确代做续接指令，不询问工具二选一。Adobe源图用asset_openai_file_upload并使用实际返回URL；每次image_apply_adjustments前须asset_inline_preview并实际看图。
2. 按本片判断合并曝光、影调与色彩参数为一次image_apply_adjustments，PNG输出。该工具的固定顺序是曝光→高光→亮部→暗部/阴影→亮度/对比→色温→HSL→自然饱和/饱和度→分通道饱和度，不把不同引擎参数当相同滑块。需要改变非交换顺序才分步。未使用的参数不补造。
3. working只续接真实taskId并记录实际调用起止，不重复提交。按当前工具要求显示实际结果，保存返回的requestId、配方与输出来源。非生成光色工具不等于自动通过保真或色彩验收。
4. 下载正式输出字节，用现有download入口完整解码后发布，保留源。核验实际尺寸、ICC/PNG声明；全幅与原生细节对照文字、画作、材质、光影与去AI味，完成问题和保护凭据。普通书画只要求与原图可见内容一致，不要求逐笔认证。PNG返回URL、JPEG预览或同尺寸预览都不是已取得的原始无损输出；不把预览缺ICC升级为原始文件偏色的结论。不能取得正式文件时记录具体阻塞，不能降低当前验收条件。工具失败不改用代码模拟调色。
5. 文件与视觉通过后，transact/accept绑定正式输出哈希与新save_result_path；实际保存成片，确认每项成功和本地身份应用，再用saved记录成片回执、身份与终点，record生成并保存精简内部记录。随后按现有delivered/版本接口登记并附版本、实际来源、保存状态和首次一次提示；不能只输出文件而跳过这些步骤。保存失败不写save_completed，不重新修图；结果未知先核实原请求，不重复提交。工具暂存、URL预览和本地文件都不替代此回执。
6. prepare/candidates/check/review凭据/accept/transact自动记录对应本地工作。外部工具与实际看图在调用前后采集时间，再stage写真实边界；render是整个API调用时间，不拆猜后端计算。不能完成时finish(status=failed/cancelled,reason,unix_ns)保留实际终点；已结束任务只读，后续新建任务。缺测保持null，绝不以流程文字补齐旧时间。

当前维护测试的能力结论记录在维护报告中；以后每次真实执行按当次可用性判断，不把一次工具可见或预览成功当成全环境稳定能力。
