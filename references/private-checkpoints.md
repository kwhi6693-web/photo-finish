# 私有任务检查点与中断恢复

仅在明确备份、长操作、验收或断点续接时使用，不增加普通修图的全库扫描。所有数据及目标 ZIP 必须位于 Skill 和所有 Git checkout 之外；宿主工作区自身也可能由 Git 管理，必须实际检查。临时磁盘与本地路径不证明跨会话持久性。

从 runtime 调用 photo_edit.py：

- `checkpoint-export`：传 `root`、`destination`、`files`。files 是相对 root 的明确文件列表，包含需要保留的原片、正式输出、失败候选、原始账本、完整工具参数/日志、保存凭据及会话索引；不自动收集不相关私图。destination 是 root 之外的新私有 ZIP 路径。
- `checkpoint-inspect`：传 `archive_path`，可传 `expected_sha256`。核验成员、大小、完整哈希、格式和路径边界。
- `checkpoint-restore`：传 `archive_path`、`destination` 和核验过的 `expected_sha256`。目标必须是新私有目录，或带同一检查点恢复日志的未完成目录。保持原始账本字节，不自动改写历史路径；恢复目录与原 root 不同时，不能直接宣称原任务可继续运行。

导出先形成完整、刷盘的本地快照，再排他发布。相同内容、同一目标重复导出返回 reused；内容变化要求新目标，不覆盖旧检查点。普通文件逐字节保留；SQLite 使用在线 backup 包含已提交 WAL 行，不盲目只复制主库文件。不同数据库/账本间不承诺同一事务快照：先暂停本任务写入，再导出。最多明确选定 1000 个文件、单项 256 MiB、总展开 2 GiB。SQLite 快照不冒充原始数据库逐字节副本。

恢复先完整校验，并在发布前再次检查实际成员哈希；只写缺失文件。中断后同一归档可继续，已存在且相同的文件复用，任何不同的历史文件都拒绝覆盖。恢复日志只属于恢复操作，不是补造的原任务日志。Windows 目录 fsync 不由当前接口提供，不承诺防止任意断电、宿主清理或硬盘故障。

本地 export/inspect/restore 一律返回 `persistent_save_confirmed:false`。随后使用宿主已有的私有保存能力，预先记录归档哈希与唯一保存意图，取得真实回执后持久保留其身份；再从持久存储取回并核验 ZIP 与关键文件哈希，才确认检查点已持久保存。外部保存结果未知时调查原意图，不重复上传。保存后、记账前中断时复用已到达的同一回执，不重新修图或保存。

检查点保存回执只证明检查点保存；不能拿它替换原成片自动保存回执，也不能从可读取文件推断已保存。若原始账本或日志已丢失，在新恢复清单中列明缺失，只保存仍有真实字节的资料，不按报告重建后冒充历史原件。原有 `backup-export/import` 继续只管理风格库/个人配置，两种归档格式不混用。私有检查点永不进入公开发行包。
