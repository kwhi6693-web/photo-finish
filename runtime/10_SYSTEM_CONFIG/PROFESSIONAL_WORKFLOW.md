# 专业摄影判断与多步精修

现行2026-10-24.3。由执行助手独立做摄影判断，无新增用户确认。审美、构图、强度与手法不设统一上限；去AI味、真实内容和实际文件验收继续有效。

1. 先看原片，明确本次用途、主体与次要层级、光线和材质的实际观察，并读取适用的可选全局指令。无自定义要求时专业自主判断，部分约束之外继续独立设计。用photo_edit.prepare检索候选，此时不锁定最终方向。
2. 参考候选传入已有意图的intent，先以元数据subject/light/material/expression解释适配性，再辅助明暗色彩排序；并非自动视觉判断。实际外部调用统一经delivery_adapter。参考候选仅为检索入口：实际比较光线方向与软硬、材质、主体语义、空间层次、预期情绪，再决定adopt/partial/reject/unavailable。把可迁移维度写入scope；同色不同光不强套白平衡，同场景不同意图不强套影调。候选不足或均不合适，立即进入专业判断，不等待补库、不伪称风格匹配。原片足以支持时独立建立新风格。 实际取舍后才确定最终意图、层级、光影材质和手法，用photo_edit.submit.direction与参考决策一起原子提交；output_use为screen或print_proof_requested，route为native/creative/hybrid。兼容低层direction也须在select后调用。该记录不是美学通过或打印认证，不要求固定调参表；默认屏幕成片不因缺RAW或打印标定而阻断。
3. 能用光色、裁切、透视或局部明暗实现的目标，优先用实际可用的非生成工具保留摄影细节；需要扩展或重塑时可用creative/hybrid，不以“原生”限制创作。文字/画作保留原图可见内容：生成结果发生变化则回退或保留原区域，不补写猜测的字，不加逐笔认证。
4. 合并可兼容的全局参数；只有构图、操作顺序或局部控制确有收益才分步。每步取得正式字节，实际看全幅、检查尺寸/色彩，必要细节通过后才做依赖该输出的下一步。可编辑任务用delivery_adapter.next-step(path,tool_name,arguments)从最新已核验输出生成新submission_id，保留历史与原片；实际结果回填相同令牌。working/unknown/未取回/未复核不能冒充下一步。已接受或终态任务不可修改：用户继续调整时新建修订任务，关联其选定成片、原图及原有保护要求，不绕过保护契约或改写历史。每步蒙版绑定当步实际输入，不能沿用变更几何前的旧蒙版。
5. 复核按本次操作覆盖：每片看全幅并实际判断所选氛围与情绪是否传达；原生尺寸只检查本次受影响的主体、文字、纹理、亮暗边缘和蒙版过渡。裁切检查重心/边缘/新尺寸；局部调整检查选区及边缘，并用实际蒙版检查选区外变化；生成操作检查结构、重复纹理和保护内容。未受影响区域不反复生成报告或裁片；边界异常再扩大检查。不是免检，也不以数值代替审美。
6. 以原片实际可用信息决定降噪、锐化与尺寸，避免为了“高清”制造纹理；保留有意的颗粒、薄雾、暗部和混合色温。“更有质感”先落实光影、明暗分离与反射层次；普通摄影保留原片材质身份、表面粗细及字纹深浅，避免以新增斑点、锈纹、纤维或锐化刻痕代替质感。明确选定材质风格化时按创作目标执行并记录。不能恢复的高光/运动模糊不宣称还原真实细节。打印用途单独获取介质ICC、软打样与目标尺寸；没有这些仍可交屏幕成片，不能声称已标定打印色准。P3正确嵌入并不等于已转换sRGB；转换必须用真实色彩管理引擎，不能只改标签。
7. 批量按相同光照建立基准，只迁移明确可共用的字段；逐张核对曝光、白平衡、几何、蒙版和噪声。规模/RAW/肤色/打印能力只按实际案例记录，不因单例通过自动扩展认证。默认编辑不跑维护回归、不补长报告。工具故障保留已得正式结果与任务状态，在保持目标和保真条件下选可用路线；不以反复重渲染或降低验收掩盖故障。

方法依据（2026-10-22检索）：
- [Adobe非破坏编辑](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/create-layer-compositions/non-destructive-editing-techniques.html)：保留原始数据与可回退的操作；当前接口输出为独立PNG和配方记录，不冒称提供分层PSD。
- [Adobe局部蒙版](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/masking.html)：局部光色控制与边缘复核；当前工具仅以实际返回的蒙版为准。
- [Adobe色彩与软打样](https://helpx.adobe.com/lightroom-classic/desktop/technical-support/technical-issues/miscellaneous-issues/color-faq.html)：按屏幕/印刷用途与真实ICC区分交付能力。

明暗与色彩补充（2026-10-24）：灰闷先辨明原因，再决定整体影调或局部分离；色彩克制与反差各按本片意图设计，低饱和＋高对比是可选组合，演示参数不通用。保留有意薄雾、柔和、高调、低调与鲜艳表达，检查实际高光、暗部、肤色和过渡，不以铺满直方图验收。按需读[理论与场景应用](TONE_COLOR_FOUNDATIONS.md)，取舍写入现有direction及终检，遵守参考use_for/uses，不增加日常调用。

默认把画面表达做得明显更充分：主动完成构图、主次光影、色彩与材质；去AI味和题字一致不等于保守微调。终检须实际比较表达目标与结果，技术通过不能替代表达完成。未落实的表达关系继续针对性修正；不机械套暖金/高饱和，也不强制每片大改。局部反馈先明确目标和参照，保留已认可的整体表达，修后检查目标、边缘和全幅协调。柔和低曝光仅作适用场景的可选表达，不成为其他照片的统一基调。

## 会话版本与保护继承

跨回合版本用photo_edit的version-register/delivered/versions/current-version定位，实际accepted输出与完整哈希为权威。继续改经revise从选定正式成片创建新任务并绑定系列原片；局部要求继承已认可direction和构图、人物保护。底层protect和accept同样验证继承条件，不能通过低层接口削弱。回退restore仅读既有文件并更新会话游标，历史照片/账本不写，不渲染；compare返回同一任务source/output，实际比较不得混版。

批量用batch-create/batch-status核对真实单张状态；batch-retry-failed只为确定未提交的失败项准备替代任务，未知提交继续调查、已完成不重复生成。每张版本注册但不重复hint，批末batch-completed统一一次。近期/常用参考来自实际接受采用记录，不推断长期爱好。
