## 原因与最小修正

当前Adobe工具合同规定：单图光色任务默认使用Display adjustments；明确要求调用后STOP，而且该工具不返回正式资产URL。服务端image_apply_adjustments允许用户明确代做等例外。仅上传照片不能推断为该例外，网页卡片报错也不能覆盖STOP。

对既有独立会话进行一次只读核查，宿主报告原返回success=true、无error/outputUrl/设备不支持/渲染失败/授权状态字段，只有summary、sessionId、requestId等。浏览器同时显示设备不支持。根检查端没有导出这次旧调用的原始返回对象；这是宿主只读报告、当前接口合同及实际UI相互对应的有限证据，不宣称所有客户端都没有可用性回调。当前提供的接口没有可用于此流程的组件失败回调，不能可靠地从卡片错误自动续接。

因此分类为：客户端不能运行交互卡片；工具路由/STOP和明确授权要求限制无预授权单图流程；Skill 2026-10-26.2要求卡片失败后继续的表述过宽，存在合同冲突。

修正ce35a5c只收紧SKILL.md、总规范及NATIVE_ADJUSTMENT_ROUTE，再用既有同步机制导出入口/镜像/哈希和候选包。编排2026-10-26.3：有明确代做授权时使用获准服务端路线；工具要求STOP时停止，不伪造故障回执或用后续保存来制造授权；没有正式URL就只记预览。条件不足说明最小明确授权续接指令，不让用户选择工具。三语言README同步说明授权边界；没有修改控制器、图像引擎、Windows持久化或保护契约。
